                              KEY CHANGES
================================================================================

COMPONENT ARCHITECTURE:
   OLD: Single client component with all logic
   NEW: Server component (data) + Client component (UI)

   OLD: Relative paths (e.g., "/uploads/image.jpg")

COMPONENT TREE:
   OLD:
      page.tsx (Client, all-in-one)

   NEW:
      page.tsx (Server, async)
      └── BlogListingContent.tsx (Client, interactive)

================================================================================
                         DATA TRANSFORMATION FLOW
================================================================================

INPUT (from Strapi API):
   - Blog posts with author, category, cover image
   - Blog categories

TRANSFORMATION:
   - Map documentId → id
   - Convert relative URLs → absolute URLs
   - Extract category slug for filtering
   - Format dates (remove time portion)
   - Calculate reading time from content length
   - Provide defaults for missing fields

OUTPUT (to React component):
   - Fully typed BlogPost objects
   - Fully typed BlogCategory objects
   - Ready for rendering in UI

FALLBACK:
   - If Strapi fetch fails, uses static data from @/lib/data
   - Site continues working with fallback data

================================================================================
                         HOW TO ADD NEW POSTS
================================================================================

STEP 1: In Strapi CMS
   - Create new Blog Post collection item
   - Fill: title, slug, excerpt, content, category, author
   - Upload cover image
   - Set publish date
   - Publish

STEP 2: On Website
   - Wait max 60 seconds for ISR revalidation
   - Post appears automatically on /tin-tuc page

NO CODE CHANGES NEEDED!

================================================================================
                      PERFORMANCE IMPROVEMENTS
================================================================================

Build-time Data Fetching:
   - Data fetched once at build time
   - Not fetched on every page request
   - Faster page loads
   - No loading states needed

ISR Revalidation:
   - Every 60 seconds, Strapi data refreshed automatically
   - Changes appear without full rebuild
   - Always serves pre-rendered HTML
   - Cache invalidation handled automatically

Bundle Size:
   - Static data file no longer needed in bundle
   - Reduced JavaScript sent to browser
   - Faster client-side hydration

Client-side Filtering:
   - Search and filtering happen client-side
   - No additional server requests needed
   - Instant feedback to user

================================================================================
                          ERROR HANDLING
================================================================================

Scenario 1: Strapi API Available
   → Uses live Strapi data
   → Site shows latest blog posts

Scenario 2: Strapi API Down (Network Error)
   → Logs error to console
   → Falls back to static data
   → Site continues working without interruption

Scenario 3: Missing Optional Fields
   - Missing cover image → Placeholder used in component
   - Missing author avatar → Conditional render (skip image)
   - Missing author role → Defaults to "Beauty Specialist"
   - Missing category → Defaults to "uncategorized"

Scenario 4: Empty Blog Posts
   → Shows "No blog posts available" message
   → Site doesn't crash
